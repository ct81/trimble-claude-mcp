RoachHarbor Privacy Policy

Last updated: November 5, 2026

This policy describes how RoachHarbor, including the Trimble Claude MCP application and Workflow Builder, handles information when you connect accounts, import files, save or run workflows, use AI chat, or use enabled messaging integrations.

Application operator and privacy contact: noodletan@outlook.com.

RoachHarbor homepage · Workflow Builder

1. Information We Process

  • Account and authorization information: account identifiers, names, email addresses, project information, OAuth access tokens and, where used by an integration, refresh tokens or session identifiers. We use OAuth sign-in rather than asking you to provide your Google or Trimble password to RoachHarbor.
  • Workflow information: workflow names, component settings, connections, prompts, selected spreadsheet and sheet identifiers, schedules, and API endpoint definitions. API headers and bodies can contain credentials or other sensitive information if you enter them.
  • Files and project data: files you select, such as PDF, Excel, CSV, IFC, or DXF files; extracted text; spreadsheet rows; workflow results; and project or model data used by connected tools.
  • Communications: messages and attachments submitted to AI chat or enabled WhatsApp and Telegram integrations, together with identifiers needed to associate messages with the relevant chat or session.
  • Technical information: request and authentication details, timestamps, caller information, and diagnostic errors. Application logs and hosting providers may record network information such as IP addresses.

2. How We Use Information

We process information to authenticate users, retrieve selected data, execute workflows, transform files, display or export results, save workflow configurations, run scheduled jobs, respond to messages, and diagnose operational problems. Connected tools may also create or modify project or model information when a workflow requests those actions.

3. Google Drive and Google Sheets

The Google Sheets import component requests read-only access to Google Drive and Google Sheets. Drive access is used to discover spreadsheets and display their names and identifiers; Sheets access is used to discover sheet names and read rows from the spreadsheet you select. These permissions are broader than access to a single selected file. The component does not request permission to edit or delete your Google files.

Google API requests are made from your browser using a Google OAuth access token. In the current Workflow Builder, that token is held in browser memory rather than saved in the workflow. Saved Google Sheets configurations contain the selected spreadsheet identifier, spreadsheet name, sheet name, and header-row preference.

Imported rows can be displayed, exported, or passed to connected workflow components. Connecting a Google Sheets component to a Claude component sends its workflow input to the application server and Anthropic. Connecting it to MCP or API components may send selected data to those configured destinations. Review your workflow and its recipients before running it.

RoachHarbor's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is not used for advertising or sold to data brokers. It is used to provide the user-facing functionality described in this policy, not to develop, improve, or train generalized AI or machine-learning models.

You can revoke the application's Google access through your Google Account connections settings. Revoking access does not delete data already exported or sent to another service.

4. AI Requests

AI chat and Claude workflow components send prompts and relevant conversation or workflow context to our server, which forwards them to Anthropic's Claude API. Context may include filenames, uploaded text, imported spreadsheet rows, and connected workflow results. Do not submit information you are not authorized to share with that provider.

Anthropic processes API requests under its applicable terms and privacy policies. This policy does not guarantee a particular third-party retention period or override that provider's terms. AI-generated results may be inaccurate and should be reviewed before use.

5. Storage, Cookies, and Retention

  • Browser storage: Workflow Builder uses local storage for settings, local workflow configurations, API definitions, and scheduled jobs. OAuth flow state is stored in session storage. Local copies remain until removed through the application or your browser's site-data controls.
  • Saved workflows: saving a workflow sends its configuration and any included uploaded files to the server. Server storage uses Firebase Realtime Database when configured, or local server disk as a fallback. Records may include an associated email address and an update timestamp. The local browser workflow copy omits uploaded file content.
  • API definitions: registered API definitions are stored locally and may also be saved to Firebase. Values you enter in headers or bodies can be included in those records.
  • Sessions: session cookies and server-side authorization records support sign-in and connected integrations. Some session data is held in server memory, while other authorization records may be persisted depending on the integration and deployment.
  • Retention: the current application does not define a universal automatic deletion period for saved workflows and API definitions. They remain until deleted or removed by the operator. Log, backup, hosting, and third-party retention depend on the respective deployment and provider settings.

Clearing the canvas or login cache does not delete saved workflows, API definitions, previously exported files, or copies held by external services.

6. Recipients and Third-Party Services

Information is shared with services needed for the features you use. These may include Google for Google Sheets and Firebase, Trimble for identity and project operations, Anthropic for Claude requests, Render for hosting, enabled WhatsApp or Telegram service providers, and MCP bridges or REST APIs selected in your workflow.

Pages may load third-party scripts or embedded content, including the Break time game and its multiplayer services. Those providers receive ordinary browser requests and may process network or device information under their own policies. Third-party destinations are responsible for their own processing and retention practices.

Information may also be disclosed where necessary to comply with applicable law, respond to lawful requests, or protect the application and its users.

7. Your Choices and Deletion

You can choose which accounts to connect, files to import, sheets to read, and workflow components to run. You can sign out, revoke connected-account permissions, remove scheduled jobs, delete saved workflows and registered APIs through available controls, and clear browser site data.

Check that a server deletion succeeds: removing a local copy alone does not necessarily remove the server record. Exports and data sent to third-party services must be managed separately. Deletion from active application storage may not immediately remove provider logs or backups.

Contact the privacy contact above to request access, correction, or deletion of information held by the operator, or to exercise privacy rights available under applicable law. We may need to verify your identity and the relevant account or workflow before acting on a request.

8. Security and International Processing

The application uses OAuth authorization and authenticated routes for protected operations. No system can guarantee absolute security. Avoid storing unnecessary secrets in workflows and review access to your deployment, browser, and connected tools.

Depending on hosting locations and connected providers, information may be processed outside your country. The applicable provider terms and deployment arrangements govern those transfers.

9. Children

RoachHarbor is intended for professional workflow and project use, not for children. If you believe a child has provided personal information, contact the operator so the matter can be reviewed.

10. Policy Updates

We keep this policy current as RoachHarbor's functionality and data practices change. The date above identifies the latest revision.

When we change how RoachHarbor accesses, uses, stores, or shares Google user data, we will publish the revised policy and update its Google data-use version and summary before introducing the change. Workflow Builder checks the published version when opened and displays a Google data-use notice linking to this policy until it is dismissed in that browser. A new version displays a new notice. Where required, we will request additional authorization or consent before accessing or using data for a new purpose.

The Privacy Policy link remains visible in the Workflow Builder toolbar and on the public homepage. Neither page requires sign-in. You can contact noodletan@outlook.com with questions about a revision.
